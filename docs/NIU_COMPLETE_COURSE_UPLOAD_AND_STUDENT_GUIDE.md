# NIU Complete Course Upload and Student Journey

This guide explains how to prepare and release one complete NIU certificate course and how a student uses it from enrollment through completion. It is written for a phone user and follows NIU’s controlled workflow:

> Prepare approved content → Create private drafts → Add the course structure → Add protected materials → Add activities and assessments → Validate → Review → Approve → Publish → Enroll → Learn → Complete → Administrator reviews eligibility → Certificate is issued

NIU is certificate-only. Uploading, generating, approving, or publishing a course does not create a degree, accreditation, license, employment guarantee, or universal recognition claim. Existing records must not be deleted or overwritten. New work should be created as a new draft version.

## Part 1 — Prepare everything before opening NIU

Create one folder on your phone or computer for the approved course materials. Keep the source curriculum, lesson notes, slides, videos, images, transcripts, question documents, assessment rules, and certificate wording together. Use clear filenames such as `module-01-lesson-01-safe-access.md` and `module-01-lesson-01-transcript.txt`.

The course should have the following approved information before upload:

| Area | Prepare |
|---|---|
| Institution structure | Existing school, new department name/code if needed, programme name/code, programme description |
| Course identity | Course title, code if used, description, level, duration, requirements, learning objectives |
| Curriculum | Ordered modules and ordered lessons; each lesson must belong to the correct module |
| Lesson design | Lesson description, objectives, estimated time, required/optional status, points, activity type, learner-support guidance |
| Learning materials | Approved private files or authorized HTTPS external resources; title, category, description, and lesson attachment plan |
| Knowledge checks | Question text, answer options, exactly one correct answer where applicable, topic, difficulty, objective mapping, and points |
| Assessments | Intended module, title, description, passing score, time limit, attempt limit, completion requirement, and attached approved questions |
| Final examination | Explicit title, rules, passing score, time limit, attempts, points, and completion requirement |
| Certificate | Approved certificate title, completion requirements, lawful certificate-only wording, transcript requirements, and signer/template settings |

Use exact approved information. Do not fill empty fields with guesses. If the curriculum does not state a passing score, correct answer, time limit, or certificate requirement, get an approved decision before continuing.

For curriculum import, prepare a clean `.md` or `.txt` document with headings that preserve order. For large media files, prepare the files individually for the protected Content Library rather than embedding them into the curriculum text.

## Part 2 — Sign in as an authorised administrator

Open the NIU website on your phone and tap **Sign in**. Use the approved NIU administrator or Super Administrator account. A student account cannot create or publish a course. If the administrator dashboard does not appear, stop and ask an authorised Super Administrator to correct the account assignment. Do not try to bypass access controls.

After signing in, open the administrator dashboard. Use the guided academic package workflow or Course Studio. The guided package is the safest starting point for a complete course because it keeps the programme, course, modules, lessons, materials, assessments, validation, review, and publication steps together.

## Part 3 — Create the academic container

### Step 1: Select the school

Inside the guided package, select the existing NIU school. Do not create a duplicate school for an existing academic domain. If the correct school does not exist, use the governed institutional workflow to create a new private draft school first.

### Step 2: Create or select the department

Create the department only if it does not already exist. Enter the approved department name and unique code. Review duplicate warnings carefully. If NIU reports that the department already exists, use the existing governed record or correct the code; do not force a duplicate.

The new department remains private and draft. Saving does not publish it.

### Step 3: Create the certificate programme

Enter the approved programme title, code, description, outcomes, difficulty, completion requirements, certificate template/settings, and lawful certificate-only wording. Confirm that the programme does not describe itself as a degree or claim accreditation, licensing, universal recognition, or employment placement.

Save the programme as a draft. Do not use a publish control at this stage. The programme will not become public merely because it was saved or because a course is added.

## Part 4 — Add the course

### Option A: Import the complete curriculum

If the course is already described in an approved curriculum document, tap **Import Complete Curriculum** inside the guided academic package. Upload the approved `.md` or `.txt` document, tap **Analyze**, and wait for the progress screen.

Review the detected department, programme, courses, modules, lessons, activities, assessments, questions, and certificate settings. Correct missing information in the source or the permitted correction controls. When validation passes, tap **Generate private draft package** once. The importer creates a new draft version and never approves or publishes it automatically.

### Option B: Build the course manually in Course Studio

If the course is not suitable for import, open Course Studio and create a new draft course under the approved certificate programme. Enter the course title, description, level, duration, requirements, objectives, and course-version information. Save once, then confirm that the course status is **Draft**.

If NIU shows a duplicate warning for the title or code, do not create another copy. Return to the existing course or obtain an approved unique identity for a new version.

## Part 5 — Build the curriculum tree

Create modules in their approved order: Module 1, Module 2, Module 3, and so on. For each module, enter its title, description, position, objectives, and supported difficulty. For curriculum imports, preserve the document order exactly.

Use the supported difficulty values shown by the course workflow. For imported module difficulty, use the approved values `introductory`, `intermediate`, or `advanced`. Do not invent a different value such as `beginner`, `basic`, or `expert` in a field that does not permit it.

Inside each module, create lessons in the approved order. Each lesson should have a title, description, objective(s), estimated time, required status, points, activity structure, and learner-support guidance where the course design requires it. Confirm that every lesson appears beneath the correct module. Do not place a lesson in a different module just to make a validation message disappear.

A required lesson must have a real learning structure. A title alone is not sufficient. Add the approved activity, reading, video, exercise, or other supported lesson structure and attach any required protected material before review.

## Part 6 — Upload protected learning materials

Open the Content Library from Course Studio or the guided package. Upload each approved document, Markdown study guide, presentation, image, audio file, video, transcript, or research resource using the displayed upload control. Enter a clear title, category, and description.

NIU stores learning files in private object storage. The uploaded file is not public. After upload, attach the library item to the exact lesson that uses it. Check the lesson title and module name before saving the attachment.

For an external resource, use only an HTTPS address that NIU is authorised to share. Mark it as an external reference rather than treating it as NIU-owned material.

Do not make a protected learning file public to solve an access problem. A learner should receive access only through an active or completed enrollment and the protected lesson route. Staff review access remains controlled by staff authorization.

## Part 7 — Add activities and knowledge checks

For each lesson, add the approved activity structure. Examples may include a reading activity, video activity, guided exercise, reflection, or knowledge check. Use only the activity types presented by NIU’s editor.

When adding a knowledge-check question, enter the complete question text, every answer option, exactly one correct answer where the question type requires one, topic, difficulty, learning-objective mapping, and points. Save it as a private question draft.

Questions remain private until their metadata is complete and an authorised staff member manually moves them into Review. A question cannot attach to an assessment merely because it was typed into the editor. Only approved questions are eligible for assessment attachment.

If the question is incomplete, do not guess the correct answer. Return to the approved curriculum owner for clarification.

## Part 8 — Create and configure assessments

Open the assessment area inside Course Studio or the governed Question Bank workspace. Tap **Create Assessment** or the equivalent create action. Enter the assessment title, description, intended module, passing score, time limit, attempt limit, points, and required-completion rule.

Every new assessment starts as **Draft**. Saving does not publish it. The system checks for duplicate assessment identities before insertion. If a duplicate warning appears, stop and use the existing assessment or correct the new title/module identity.

Attach only questions whose status is **Approved**. Confirm that every attached question belongs to the correct question bank, has a valid answer key, has positive points where required, has supported difficulty and topic metadata, and maps to a valid learning objective. An attached question cannot bypass approval.

For the assessment itself, confirm the following:

| Rule | Check before Review |
|---|---|
| Passing score | Within the permitted range and consistent with the points available |
| Time limit | Positive and appropriate for the assessment |
| Attempt limit | Positive whole number and consistent with the course policy |
| Required completion | Explicitly enabled or disabled according to the approved course rule |
| Intended module | Exact module selected; no orphan assessment |
| Questions | Approved questions only; no unresolved answer keys |
| Points | Question and assessment points are valid and internally consistent |

If any requirement fails, NIU blocks the transition and explains what must be corrected.

Create a final examination only when the approved course design contains one. Configure its title, placement, passing score, time limit, attempts, points, completion rule, and approved questions. Do not create an examination merely because it is common in other courses.

## Part 9 — Configure completion and certificate settings

In the course or programme completion settings, enter the approved completion rules. These may include required lessons, required assessments, passing scores, final examination requirements, total points, or other explicitly approved conditions.

Check that the certificate settings match the programme’s certificate-only scope. Use the approved certificate title and signer presentation. Do not claim a degree, accreditation, license, professional registration, employment guarantee, partnership, or universal recognition.

Certificate eligibility is calculated from authorised records. Completing a course does not directly issue a certificate. The system can create an eligible candidate, but an authorised administrator must review and approve issuance.

## Part 10 — Validate the full draft package

Use Course Studio’s validation or checklist panel. Review every blocker from top to bottom. A complete course should have the following relationships:

- one approved department relationship;
- one certificate programme relationship;
- one course and course version;
- ordered modules;
- ordered lessons under the correct modules;
- objectives for the course, modules, and lessons where required;
- learning structure for required lessons;
- protected materials attached to the intended lessons;
- question banks with complete private questions;
- assessments attached to the intended modules;
- approved questions attached to assessments;
- valid answer keys, topics, difficulties, objective mappings, and points;
- valid passing scores, time limits, attempt limits, and completion rules;
- certificate settings consistent with the certificate-only policy.

Fix every validation error. Do not use a placeholder answer, placeholder objective, or guessed rule. If a required field is not known, the course is not ready for Review.

## Part 11 — Review the draft as an administrator

Open the generated or manually created draft in Course Studio and review it as a complete package. Use the curriculum tree rather than reviewing only the course summary.

Check the module order, lesson order, lesson/module relationships, objective mappings, material attachments, question banks, assessment attachments, final examination placement, completion rules, certificate settings, and public description. Read the learner-facing wording for unsupported claims.

Use individual correction controls for approved changes. If a section remains incomplete, use **Regenerate incomplete sections** only after correcting the source or approved metadata. Review regenerated sections again. Regeneration is not approval.

## Part 12 — Move records through governance

The governed lifecycle is:

> Draft → Review → Approved → Published → Archived

Move a record from Draft to Review manually only when its information is complete. An authorised reviewer must approve the course package and its related content. The system does not approve content automatically after import or after validation.

If a record is Published, do not accidentally return it to Draft. Future corrections should follow the governed versioning or archival process. Do not delete an existing published record to replace it with an import.

## Part 13 — Publish the course deliberately

After review and approval, return to the guided academic package. Confirm the readiness summary. Use the existing controlled publication action only when all prerequisites pass. Publication requires authorised staff action and is not triggered by saving, generating, attaching a file, or approving a question.

If publication is blocked, read the exact readiness message. Correct the specific missing module, lesson, material, question, assessment rule, or certificate setting. Do not bypass the publication gate with direct database edits.

After publication, open the public programme and course pages. Confirm that only Published records appear publicly. Draft and Review records should remain private. Public pages must continue to use certificate-only wording.

## Part 14 — Enroll as a student

For a real student, sign out of the administrator account or use a separate approved student account. Open the published course page and tap **Enroll in this course**. Enrollment requires an active NIU account and a Published course. Prerequisites, if any, must be completed.

The enrollment workflow is server-controlled. It records an active enrollment using the live enrollment status model and prevents a student from changing their own role or gaining staff access. If the course is not published or a prerequisite is missing, enrollment is blocked with a message.

After enrollment succeeds, tap **Go to My Learning**. The course should appear under the student’s active courses. If it does not, refresh the page once and confirm that the same student account is still signed in.

## Part 15 — Student learning journey

From **My Learning**, tap the course and then **Continue learning**. Open the first module and lesson in order. Read or watch the protected material through the lesson page. The material should be available because the student has an active enrollment; it should not be exposed through a public file URL.

Complete each lesson activity. Use the lesson’s **Mark activity complete** control only after completing the activity. NIU validates completion on the server against the active enrollment. Continue through every required lesson and module.

If the student leaves and returns later, open **My Learning** and continue from the recorded progress. Do not use an administrator route as a student and do not attempt to open a protected storage path directly.

## Part 16 — Student assessments

When an assessment becomes available, open it from the intended module. Read the instructions, confirm the attempt rules, and begin the attempt. Answer each question. The assessment uses the approved questions and answer keys attached by staff.

Submit the attempt through the assessment control. Do not refresh repeatedly during submission. Submitted attempts are governed records; the student cannot alter a submitted answer key or rewrite a released result.

After grading and release, the student can see the released outcome in the student learning area. If the assessment is not available, the course may not have reached the required lesson or publication state, or the administrator may still be reviewing it.

## Part 17 — Completion and certificate eligibility

The student must complete the required lessons, required activities, required assessments, passing scores, final examination, and any other approved completion rules. Progress and grades are derived from NIU records rather than from a client-side percentage alone.

When the server-calculated requirements are satisfied, NIU can create or refresh a certificate candidate with an eligibility status. This is not automatic issuance. An authorised registrar or administrator must review the candidate and approve issuance.

After approval, the student can retrieve the certificate, transcript, and any issued supporting institutional documents through the protected student credentials area. The certificate includes lawful certificate-only wording and the approved founder/signature presentation. Public verification exposes only the minimum credential information intended for verification and never exposes the student’s course-level learning data.

## Part 18 — Troubleshooting on a phone

If the upload does not start, confirm the file type, file size, filename, and internet connection. If analysis reports missing information, return to the source document and add the approved field rather than guessing. If a duplicate warning appears, do not submit repeatedly; review the existing draft or correct the new version identity.

If a protected material does not open, confirm that the student is signed in to the enrolled account and that the lesson belongs to the enrolled course. Do not make the file public. If an assessment is blocked, read the validation message and check the module relationship, approved-question status, answer key, points, passing score, time limit, attempt limit, and completion rule.

If a certificate does not appear immediately after completion, check the student’s progress and released grades first. Certificate issuance remains administrator-controlled. A student should not receive an automatically issued credential merely because a progress bar reaches 100 percent.

## Final complete-course checklist

Before telling students that the course is ready, confirm that the department, programme, course, modules, lessons, objectives, protected materials, activities, question banks, questions, assessments, final examination, completion rules, and certificate settings have all passed validation. Confirm that the course is Approved before publication, that the existing publication gate succeeds, that the public catalogue shows only Published content, that enrollment works for a real student account, that protected materials require enrollment, and that at least one student can complete the intended learning path without accessing administrator routes.

The safe completion state is not “uploaded.” It is **approved and deliberately published**, followed by a verified student enrollment and protected learning walkthrough. Keep all other drafts private until they have passed the same governed process.
